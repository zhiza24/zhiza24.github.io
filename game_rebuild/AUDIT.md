### tests
- Существуют проверки профиля, паспорта, зеркал, заданий, сцен открытия и карты. Их нужно изучить и адаптировать для новой сборки, не удаляя и не переписывая исходные тесты.

## 3. Принципиальные вопросы, которые нельзя решать молча

1. Единая карта: сохранить 40-шаговую структуру game_v5, территории game_gemini или сделать связку «пять крупных этапов + внутренняя карта шагов»?
2. Трекер: 21 день, 28 дней или четыре недели с иным числом контрольных точек?
3. Обязательность даты рождения: игровой паспорт/символика отдельно от исследовательской диагностики; не делать дату условием прохождения психологических модулей без авторского решения.
4. Глубина исследований: какие тесты нужны в обязательном маршруте, какие — по запросу/в дополнительных комнатах?
5. Результаты: как объединять данные разных модулей, не складывая несопоставимые шкалы в один псевдодиагноз?
6. Переходы: какие результаты открывают следующие сцены, а какие только формируют гипотезы и рекомендации?
7. Артефакты: условия получения должны быть связаны с фактически пройденными этапами/действиями, а не выдаваться автоматически.

## 5. Уточненное правило свежести исходников

Автор подтвердила: в новую сборку нужно брать наиболее свежие доработанные редакции по каждому материалу. Нельзя объявлять целую папку безусловно приоритетной только из-за названия/номера версии.

Для каждого файла/модуля:
1. Проверить историю Git по конкретному пути и связанные коммиты.
2. Сверить содержание последних редакций, включая данные, ключи, алгоритмы и тексты.
3. Проверить зависимости: актуальная HTML-страница может подключать JS/CSS/data из соседних файлов, которые тоже необходимо брать согласованно.
4. Зафиксировать путь-источник и commit SHA в таблице происхождения.
5. Если изменения противоречат друг другу, описать выбор и причину, не сливать автоматически.

На момент первичной проверки последняя видимая серия изменений основной ветки включает коммит `9bad5dc7222fe3d553b3141a5e8719d4d3aa0bb8` с обновлениями `game_v5`: карта героя, финал с картой, личные тексты дневника, экран героя и повторное прохождение пропущенных тестов. Это подтверждает, что отдельные части game_v5 дорабатывались поздно; но не доказывает, что каждый файл game_v5 новее соответствующего материала в других каталогах. Поэтому нужен аудит по каждому модулю.
