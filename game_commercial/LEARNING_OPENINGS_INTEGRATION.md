# «Открытия» — пакет для проверки и интеграции в game_v5

Ветка: `feature/learning-openings`.

## Состав

- `learning-data.js` — 8 готовых русскоязычных мини-обучений, вопросы, обратная связь, карточки, схемы, необязательные практические поля.
- `learning-engine.js` — независимый движок отображения, проверки ответов, карточек и локального прогресса.
- `learning.css` — адаптивный интерфейс в палитре game_v5.
- `learning.html` — самостоятельная библиотека/просмотрщик для ручной проверки.
- `sw.js` — обновлен до cache v64 и включает четыре новых файла в precache.

## Как открыть для проверки

Открыть в опубликованной ветке-предпросмотре (после временного Pages preview или локального сервера):

`game_v5/learning.html`

Все восемь уроков доступны в библиотеке. Прямой адрес урока:

`learning.html?opening=fact-interpretation`

Идентификаторы:
- `fact-interpretation`
- `inner-rules`
- `desire-intention`
- `observe-without-judgment`
- `impulse-to-completion`
- `habit-design`
- `inner-resistance`
- `see-change`

## Предлагаемая карта встраивания

Это карта-кандидат, основанная на текущем `GFLOW` в `flow.js`. Она не добавляет новые обязательные шаги и не меняет порядок маршрута.

| Opening ID | Контекст/триггер-кандидат |
|---|---|
| fact-interpretation | после `slot.html?id=im` — Зал зеркал / синтез исследований |
| inner-rules | после `betray.html` — Колесо самопредательства |
| desire-intention | после `wish.html` — Небо желаний |
| observe-without-judgment | перед началом `reactor.html` |
| impulse-to-completion | внутри практики «Выбираю — делаю — сделано» в Реакторе |
| habit-design | внутри вкладки/практики привычек в Реакторе |
| inner-resistance | контекст поддержки при пропуске привычки/аскезы |
| see-change | перед финальным сравнением `slot.html?id=compare` |

Первые четыре и финальное открытие имеют естественные сюжетные точки. Три открытия, относящиеся к практикам Реактора, должны вызываться из соответствующих экранов/событий практики, а не вставляться в маршрут GFLOW.

## Важное для интегратора

1. Никакие файлы основного маршрута, `flow.js`, `route.js`, `map.html`, `reactor.html` в этой ветке не переписаны для подключения модуля.
2. Существующие ID маршрута, тестов, расчеты и сохранения не менялись.
3. Модуль сохраняет данные в том же `localStorage.alch_v5_profile`, в отдельном поле `learning`. Не заводит отдельный профиль.
4. Тексты практических заметок сохраняются локально в `learning.practice`; ответы на вопросы хранят только счетчик попыток, а не выбранные варианты. Личные тексты не отправляются в сеть.
5. Уроки не заблокируют прохождение при ошибке или пропуске. Артефакт означает завершение урока, а не оценку личного качества.
6. Перед production-интеграцией проверить экспорт/импорт профиля: если сериализация профиля копирует только whitelist-поля, добавить `learning` в этот whitelist.
7. После подключения проверить precache: cache v64 уже включает новые ресурсы. При объединении с параллельными изменениями SW согласовать номер версии и список ASSETS, не затирая чужие изменения.
8. Ветку не сливать автоматически. Сначала выполнить аудит, локальные тесты, мобильный/десктопный walkthrough и сверить микрокопирайтинг с автором.

## Проверки, которые должен выполнить Grok

- Синтаксис всех трех JS-файлов.
- Все восемь уроков отображаются; ни один вопрос не имеет отсутствующего правильного ответа.
- Сохранение `learning.completed`, `learning.attempts`, `learning.cards`, `learning.practice`.
- Сохранение после перезагрузки и закрытия вкладки.
- Старый профиль без поля `learning` открывается без миграции и потери данных.
- Экспорт/импорт профиля сохраняет `learning`.
- Offline после установки/обновления Service Worker.
- iOS Safari, Android Chrome, desktop.
- Никакого автоматического изменения GFLOW/тестов/психологических результатов.
